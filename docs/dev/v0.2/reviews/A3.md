## 2. 규칙별 검증 결과

### 2.1 CON-001 (SSOT 원본 무수정 원칙) — 통과
- `git diff --no-index`를 통해 원본 anomalib 파일과 포팅 파일 간 비교를 수행하였다.
- 모든 모델 파일에서 **import 경로 치환 이외의 코드/로직/하이퍼파라미터 변경은 0줄**임을 실측 확인하였다.
- 원본 docstring 내 Lightning 관련 설명도 임의로 삭제하지 않고 원본 그대로 보존하였다.

### 2.2 CON-002 (Lightning 완전 배제) — 통과
- `src/tasks/anomaly/models/`, `src/tasks/anomaly/adapters/`, `configs/anomaly/models/` 전체에 대해 `lightning`, `pytorch_lightning`, `LightningModule`, `Trainer` import 및 호출 여부를 전수 검사하였다.
- 잔재 0건 확인.

### 2.3 CON-003 / CON-004 (오프라인 실행 및 로컬 자산 강제) — 통과
- `build_fre`, `build_uflow`, `build_csflow`, `build_supersimplenet` 팩토리에서 네트워크 다운로드 경로가 완전히 차단됨을 확인하였다:
  - `timm.create_model` 호출 시 `pretrained=False` 래핑
  - `torchvision.models.efficientnet_b5` 호출 시 `weights=None` 래핑
- 로컬 가중치 누락 또는 구조 불일치 시 `LocalAssetError`로 즉시 실패하는 strict 검증 로직이 구현되었다.

### 2.4 NFR-005 (Task-Agnostic 공통 Engine) — 통과
- `src/core/engine.py` 및 `src/core/builders.py`에 모델명이나 태스크명 분기(`if model == ...`, `if task == ...`)가 전혀 없음을 확인하였다.
- 다중 파라미터 그룹 최적화 지원을 위해 `TaskAdapter.configure_optimizers` 다형성 훅을 도입하여 공통 engine의 task-agnostic 성격을 완벽히 보존하였다.

## 3. 지적 사항 및 조치 내역

### 지적 1 (Major) — SuperSimpleNet의 분리 학습률(Split LR) 미반영
- **위반 항목**: CON-001 (Upstream 동등성 및 재현성)
- **원인**: upstream `Supersimplenet.configure_optimizers`는 `adaptor` 파라미터 그룹에 `lr: 1e-4`, `segdec` 파라미터 그룹에 `lr: 2e-4`를 부여하여 학습한다. 초기 포팅에서 단일 global `lr: 0.0002`를 적용하여 `adaptor`가 2배 빠른 학습률로 학습되는 괴리가 발생함.
- **조치**:
  1. `TaskAdapter`에 `configure_optimizers(self, model, config_optim)` 훅 추가.
  2. `SupersimplenetAdapter`에서 `configure_optimizers`를 오버라이드하여 `adaptor`(`lr=1e-4`), `segdec`(`lr=2e-4`, `weight_decay=1e-5`)로 분리된 `AdamW` 옵티마이저를 생성하도록 수정.
  3. 스모크 재실행(`train.py`, 1 epoch) 결과 `lr=1.0e-04`로 정상 스텝 및 학습 완주 확인.
