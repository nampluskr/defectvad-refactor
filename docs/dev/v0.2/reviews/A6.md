| WinCLIP | `image/winclip/` | CLIP 텍스트-이미지 프롬프트 앙상블 유사도, no-gradient zero-/few-shot |

신규 공유 컴포넌트: `src/tasks/anomaly/models/components/base/buffer_list.py` (`BufferListMixin`, 파일째 신규 복사).

## 2. 규칙별 검증 결과

### 2.1 CON-001 (SSOT 원본 무수정 원칙) — 통과
- `torch_model.py`는 `InferenceBatch`/`BufferListMixin`/`DynamicBufferMixin` import 경로 3곳 치환 외 diff 0줄. `prompting.py`, `utils.py`, `buffer_list.py`는 원본과 완전 동일.

### 2.2 CON-002 (Lightning 완전 배제) — 통과
- 신규 코드 실행 경로상 Lightning import/호출 0건.

### 2.3 NFR-005 (Task-Agnostic 공통 Engine) — 통과
- `src/core/`에 대한 변경 0건. `build_anomaly_transform`에 추가된 `mean`/`std`/`interpolation`은 모델명 분기가 아닌 일반 파라미터.

### 2.4 CON-003 / CON-004 (오프라인 실행 및 로컬 자산 강제) — 통과
- `build_winclip()`의 `open_clip.create_model_and_transforms` monkeypatch가 `pretrained=None`으로 다운로드 분기를 차단하고, `try/finally`로 원상복구됨을 확인.

### 2.5 anomalib 동등성 — 지적 2건, 모두 수정 완료

- **지적 1 (Major) — few-shot 참조 이미지 수집 시점 불일치**: `WinclipAdapter`가 참조 이미지를 첫 validation 직전(즉 "학습" pass 이후)에 수집했다. Upstream `WinClip.setup()`은 Lightning `setup(stage)` hook으로 `trainer.fit()` 시작 **전**에 호출된다. `loaders["train"]`이 shuffle이므로, 학습 pass가 먼저 그 loader를 한 번 순회한 뒤 참조 이미지를 뽑으면 upstream이 뽑는 표본과 순서가 달라진다.
  - **조치**: 임베딩 수집 로직 전체(`on_validation_start` → `on_fit_start`로 이동)를 학습 루프 시작 전(`Engine.fit()`이 `adapter.on_fit_start()`를 호출하는 시점, `src/core/engine.py:45`)으로 옮겼다. `loaders` dict는 이 시점에 이미 `{"train", "valid"}` 키를 모두 갖고 있어 `class_name` 추론 로직 변경은 불필요했다.
  - **영향 범위**: `evaluate.py`/`predict.py`는 `Engine.evaluate()`/`Engine.predict()`가 `on_fit_start`/`on_validation_start`를 전혀 호출하지 않으므로 무관하다 — 체크포인트에 저장된 `_text_embeddings`/`_visual_embeddings` persistent buffer를 그대로 쓴다.
- **지적 2 (Minor) — `class_name=""` 처리 차이**: `self.class_name or self._infer_class_name(loaders)`가 명시적 빈 문자열을 미지정으로 취급했다. Upstream `_get_class_name()`은 `None`만 미지정으로 본다.
  - **조치**: `self.class_name if self.class_name is not None else self._infer_class_name(loaders)`로 변경.

### 2.6 dummy loss 안전성 — 통과
- Detached leaf 0-loss이며, engine이 매 step `zero_grad(set_to_none=True)`를 수행하므로 CLIP 파라미터에 gradient가 도달하지 않아 optimizer step은 no-op임을 확인.

## 4. 최종 결론

WinCLIP은 지적된 Major 1건(few-shot 참조 이미지 수집 시점)과 Minor 1건(`class_name` 빈 문자열 처리)을 모두 수정했으며, Critical 지적은 없었다. SSOT 무결성, Lightning 배제, 오프라인 실행, 공통 engine 비오염성을 포함한 나머지 검증 항목을 모두 통과하여 WinCLIP 포팅을 승인한다. 3개 카테고리(bottle/carpet/capsule) 기준 정식 성능 비교는 여전히 사용자 실행 대기 상태다.
