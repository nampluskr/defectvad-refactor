## 1. 검증 개요

`docs/dev/v0.2/PLAN.md`의 Phase 7 (Tier 3 Foundation Model 계열 포팅)에 정의된 3개 모델에 대해 anomalib v2.3.0 원본과의 SSOT 무결성, Lightning 의존성 완전 제거, 로컬 자산 오프라인 실행, 공통 engine 비오염성, DINOv2 백본 공유 컴포넌트의 동등성을 검증하였다.

| 모델 | SSOT 원본 경로 | 주요 아키텍처 / 학습 패러다임 |
|---|---|---|
| UniNet | `image/uninet/` | Teacher-Student (source/target teacher 이중 구조) + attention bottleneck + DFS, split-LR AdamW |
| Dinomaly | `image/dinomaly/` | DINOv2 ViT encoder(frozen) + bottleneck/decoder reconstruction, per-step WarmCosineScheduler |
| AnomalyDINO | `image/anomaly_dino/` | DINOv2 ViT feature + PatchCore 스타일 memory bank (no-gradient, fit-only) |

공유 신규 컴포넌트: `src/tasks/anomaly/models/components/dinov2/` (DINOv2 backbone 전체 포트: loader, vision transformer, layers 8종), `src/tasks/anomaly/models/components/data/utils/download.py`.

## 2. 규칙별 검증 결과

### 2.1 CON-001 (SSOT 원본 무수정 원칙) — 통과
- 복사된 모든 모델/컴포넌트 파일에서 import 경로 치환 이외의 코드/로직/하이퍼파라미터 변경 0줄 확인.

### 2.2 CON-002 (Lightning 완전 배제) — 통과
- 신규 코드 전체에서 실행 경로상 Lightning import/호출 0건 확인 (docstring 언급만 잔존, 원본 보존 목적으로 무수정).

### 2.3 NFR-005 (Task-Agnostic 공통 Engine) — 통과
- `src/core/`에 대한 변경 0건 확인.

### 2.4 CON-003 / CON-004 (오프라인 실행 및 로컬 자산 강제) — 지적 2건, 1건 수정
- **지적 1 (Critical) — DINOv2 다운로드 경로 잔존**: `DinoV2Loader`가 요청 파일이 없으면 `_download_weights()`로 폴백한다. `weights_path`가 가리키는 디렉터리에 `encoder_name`에 대응하는 정확한 파일명이 없으면(예: selector와 어긋난 `--set` 오버라이드) 조용히 네트워크 다운로드를 시도할 수 있었다.
  - **조치**: `components/dinov2/local_preflight.py`를 신설해 `DinoV2Loader`의 이름 파싱/경로 결정 로직(`_parse_name`, `_get_weight_path`)을 그대로 재사용하여 실제 요청될 파일의 존재를 생성 전에 강제 검증하고, 없으면 `LocalAssetError`로 즉시 실패하도록 `build_dinomaly`·`build_anomaly_dino`에 추가했다.
- **지적 2 (Critical) — UniNet `weights_path=None` 시 teacher 랜덤 초기화**: `build_uninet(weights_path=None)` 호출 시 두 teacher가 조용히 랜덤 초기화된 채로 통과한다.
  - **판정**: 이는 이 포팅에 국한된 결함이 아니라 `PatchCore`/`PaDiM`/`DFM`/`DFKDE`/`ReverseDistillation` 등 기존 9개 이상 모델에 이미 존재하는 프로젝트 전역 설계(`weights_path=None` → optional-random-init)이며, A1 검토에서 이미 지적되고 "9개 모델에 걸친 기존 설계라 이번 세션에서는 수정하지 않는다"로 명시적으로 유보된 사안(`UPSTREAM-INVENTORY.md` §14)과 동일 패턴이다. 실제 배포 config는 항상 `weights_path`를 채워 넣으므로 이 경로는 도달하지 않는다. **범위 밖으로 유보, 별도 core 차원 과제로 이월.**

### 2.5 Optimizer/Scheduler 충실도 — 지적 1건(Major), 수정 완료
- **지적 3 (Major) — Dinomaly의 engine 옵티마이저가 stale gradient를 흡수**: `DinomalyAdapter.train_step`이 private optimizer로 `zero_grad → backward → step`을 수행한 뒤 `.grad`를 다시 비우지 않아, engine이 반환된 zero dummy loss에 대해 `backward()`를 호출해도 기존 `.grad`가 그대로 누적(대체가 아닌 가산)된 채 남고, engine 자신의(원래는 no-op이어야 할) optimizer가 그 stale gradient로 실제 업데이트를 한 번 더 가하는 결함이었다. `CflowAdapter`가 동일 패턴에서 이미 마지막 fiber 뒤에 `zero_grad()`를 추가로 호출해 이 문제를 막고 있었는데, Dinomaly 포팅 시 이 세부사항을 누락했다.
  - **조치**: `private_optimizer.step()` 직후 `private_optimizer.zero_grad()`를 추가해 CflowAdapter와 동일한 방식으로 봉쇄했다. 수정 후 2-epoch 재검증에서 정상 수렴 확인 (`image_auroc=1.000`, `pixel_auroc` 0.985→0.989).

### 2.6 UniNet 세부 검증 — 통과
- `source_teacher`의 인스턴스 수준 `train` 오버라이드가 공통 engine의 매 epoch `model.train()` 재귀 호출에도 eval 고정을 유지함을 확인.
- split-LR 파라미터 그룹(student+bottleneck+dfs @ base lr, target_teacher @ 1e-6)이 정확히 구성됨을 확인.
- MVTec train split의 빈 target(`{}`)에 대한 all-zero-label 대체가 `UniNetLoss`상 실제 all-zero per-pixel mask와 수학적으로 동치임을 확인.

## 4. 최종 결론

Phase 7 대상 Tier 3 모델 3종(`UniNet`, `Dinomaly`, `AnomalyDINO`)은 지적된 Critical 1건(DINOv2 다운로드 경로)과 Major 1건(Dinomaly gradient 누수)을 수정 완료했으며, 남은 Critical 1건(UniNet `weights_path=None` 랜덤 초기화)은 프로젝트 전역에 걸친 기존 설계와 동일 패턴으로 확인되어 A1 검토 당시와 동일하게 범위 밖으로 유보한다. 나머지 아키텍처/품질 제약 조건을 모두 충족하므로 Phase 7 완료를 승인한다.
