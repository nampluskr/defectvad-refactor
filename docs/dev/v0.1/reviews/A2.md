## 공격 축별 검토자 확인 사항

검토자가 명시적으로 검증했다고 보고한 항목(요약, 상세는 프롬프트의 공격 축 1~9 참조):

1. `upstream/` 원본 손상 없음 — 관찰된 변경은 SPEC §3이 지정한 로컬 import 경로 치환뿐.
2. Lightning 잔재 없음 — 신규·변경 파일에서 실행 가능한 lightning import·호출 경로 미발견(주석/docstring의 `lightning_model.py` 언급은 참조용 서술일 뿐 import가 아님).
3. anomalib 동등성 — `StfpmAdapter.train_step`이 `STFPMLoss(teacher_features, student_features)`를 추가 스케일링 없이 그대로 호출함을 확인. `to_output_dict()`의 `squeeze(1)`이 STFPM의 `(B,1)`/`(B,1,H,W)` singleton 축을 값 손실 없이 제거함을 `torch_model.py`+`anomaly_map.py` 대조로 확인.
4. 공통 engine 오염 없음 — `core/*.py`와 `to_output_dict()`/`AnomalyAdapter` 경로에 모델명·task명 분기 없음(shape/타입 기반 판정만 사용).
5. lifecycle hook — STFPM은 `on_fit_end`를 override하지 않으므로 P1이 검증한 상속 동작(`compute_thresholds`가 valid만 사용) 그대로 유지됨을 확인.
6. 오프라인 위반 없음 — `timm.create_model` 패치가 teacher 생성 구간에서만 `pretrained=False`를 강제하고 `try/finally`로 원복됨을 확인. 로컬 가중치 부재·키 불일치는 모두 `LocalAssetError`로 실패하며 조용한 랜덤 초기화 폴백 없음.
7. train/eval 경계 — 평가·예측 경로가 `model.eval()` + `torch.no_grad()` 아래에서 실행됨을 확인.
8. frozen 파라미터 — `core/engine.py`의 매 epoch `model.train()` 호출에도 불구하고, upstream `TimmFeatureExtractor.forward()`가 `requires_grad=False`일 때 자체적으로 `feature_extractor.eval()` + `torch.no_grad()`를 재적용해 teacher가 self-heal됨을 확인. teacher 파라미터는 `requires_grad=False`이고 `build_optimizer`의 trainable 필터에서 제외됨.
9. 재현성 — 이 Phase에서 seed/RNG 관련 변경 없음.

추가로 `src/core/offline.py#load_local_weights` 반환 시그니처 변경(`model` → `(model, missing, unexpected)`)이 기존 5개 호출부(`classification/models/efficientnet_b0.py`, `resnet50.py`, `detection/models/fasterrcnn_r50_fpn.py`, `segmentation/models/deeplabv3_resnet50.py`, `fcn_resnet50.py`)에 영향 없음을 확인 — 모두 반환값을 버리는 단문 호출.
