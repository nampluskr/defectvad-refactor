2. **Lightning 잔재 (CON-002)**: 지적 없음. import·의존성·호출 경로에서 발견되지 않음.
3. **anomalib 동등성**: 지적 없음. loss 구성, auxiliary transform, teacher 통계 산출 순서, train 전용 통계, valid의 normal 샘플만 사용하는 calibration, 90%/99.5% 분위수 계산이 문서화된 semantics와 일치.

7. **train/valid/test 누수**: 지적 없음. teacher 통계는 train만, calibration·threshold는 valid만 사용하며 calibration은 normal 샘플만 필터링.
8. **frozen 파라미터**: Minor 2건 (아래).

### Minor #1 — calibration 파라미터가 optimizer에 포함됨

- 위치: `src/tasks/anomaly/adapters/efficientad.py` (수정 전 168행 부근, `build_efficientad`)
- 재현 조건: `EfficientAdModel` 생성 → `build_optimizer` 호출 → optimizer 파라미터가 `student`+`ae` 외에 `mean_std`/`quantiles`의 6개 텐서를 추가로 포함.
- 위반: SPEC §4.2, §4.5 (anomalib은 `student`+`ae`만 최적화 대상으로 명시).
- 처리: **수정 완료.** `build_efficientad`가 `model.mean_std`/`model.quantiles`를 생성 직후(=`build_optimizer`가 `model.parameters()`를 캡처하기 전) `requires_grad=False`로 고정하도록 변경. `nn.ParameterDict.update()`가 이후 새 `Parameter` 객체로 교체하며 `requires_grad=True`로 되돌리는 문제가 있어, `on_fit_start`/`on_fit_end`의 `.update()` 직후에도 재고정(`_freeze()`)을 추가해 모델의 실사용 buffer 상태도 일관되게 유지. 수정 후 `optimizer 파라미터 수 == student+ae 파라미터 수`를 스크립트로 확인(5,363,712 == 5,363,712).

### Minor #2 — teacher가 학습 중 eval 모드를 유지하지 못함

- 위치: `src/tasks/anomaly/adapters/efficientad.py` (수정 전 64/168행 부근)
- 재현 조건: 모델 생성 시 `model.teacher.training is False` → `Trainer._train_epoch`가 매 epoch `model.train()` 호출 → `model.teacher.training is True`로 바뀜.
- 위반: SPEC §4.5, AGENTS.md frozen 파라미터 검토 축. 현재 teacher(PDN)는 BatchNorm/Dropout이 없어 수치 영향은 없다고 검토자도 명시.
- 처리: **수정 완료.** `build_efficientad`에서 `model.teacher.train`을 인스턴스 단위로 오버라이드해 항상 `eval()`로 귀결되도록 바인딩(`types.MethodType`). STFPM upstream의 `TimmFeatureExtractor.train()` 자체 오버라이드와 동일한 취지이며, `upstream/` 파일은 수정하지 않음(CON-001 미저촉). 수정 후 `model.train()` 호출 뒤에도 `model.teacher.training is False`, `model.student.training is True`를 스크립트로 확인.
